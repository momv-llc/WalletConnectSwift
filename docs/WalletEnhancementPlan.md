# План улучшений ODIN Wallet перед релизом

Ниже — сводка существующего функционала библиотеки `WalletConnectSwift` (может использоваться в ODIN Wallet) и приоритетных доработок, чтобы усилить функциональность и UX кошелька перед релизом.

| Что уже есть (по SDK) | Что добавить перед релизом (кошелёк) |
| --- | --- |
| Поддержка WalletConnect 1.x: управление сессиями (создание, реконнект, разрыв) и обновление сессий для кошелька. | Обновить на WalletConnect 2.0 с поддержкой нескольких цепочек, push-уведомлений и более безопасного установления связи. |
| Обработчики JSON-RPC 2.0 с `Codable`: `personal_sign`, `eth_sign`, `eth_signTypedData`, `eth_sendTransaction`, `eth_signTransaction`, `eth_sendRawTransaction`, возможность кастомных методов. | Добавить дефолтные хендлеры под ODIN CHAIN и популярные EVM-методы (EIP-1559, типы 0/2/1559), а также абстракции под мультичейн (BSC, Ethereum). |
| Готовые примеры соединений через QR/Deep Link (пример приложения кошелька). | Встроить полноэкранный сканер QR + универсальные ссылки, автопереподключение, кэширование сессий и раздел "Недавние dApp". |
| Базовое логирование с уровнями для отладки. | Централизованный лог/телеметрия (например, Sentry/ELK), экран статуса соединения и диагностики сети внутри кошелька. |
| Чистые Swift API для интеграции в iOS/macOS. | Кроссплатформенный UI-кит (SwiftUI) с тёмной/светлой темой, адаптивными карточками активов и UX-паттернами (pull-to-refresh, skeleton loading). |
| Возможность отправки пользовательских RPC-запросов через клиента. | UI-консоль/"Developer Mode" в кошельке для отладки dApp-интеграций и просмотра исходящих/входящих RPC с фильтрами. |
| Пример обработки ошибок на уровне ответа. | Расширенные статусы транзакций: ожидание, подтверждение, неуспех, реплей, с push-уведомлениями и локальными напоминаниями. |
| Разруливание ответов в формате `Decodable`. | Экран истории транзакций с группировкой по dApp/токену, возможностью экспорта и повторной отправки. |
| Готовая серверная часть (кошелёк-сторона) для приёма запросов. | Модуль безопасного хранения ключей: Secure Enclave + биометрия, разделение кошельков (личный/рабочий), многоподписные сценарии. |
| Пример клиента (dApp-сторона) для отправки запросов. | Встроенный браузер dApp/универсальный deeplink-хэндлер с проверкой домена, предупредительными экранами и списком доверенных dApps. |
| Поддержка подписания стандартных сообщений/транзакций. | UX для управляющих операций ODIN: стейкинг, вестинг, голосование, управление сервис-нодами, покупка ODIN через on-ramp. |
| Минимальные требования iOS 13/macOS 10.14, Swift 5. | Полноценное онбординг-фаулт-толеранс: резервное копирование seed (12/24 слова), проверка фразы, шифрование бэкапа в облаке, пошаговые подсказки. |
| MIT-лицензия, открытая для форка. | Брендинг ODIN: экран приветствия, кастомные темы, иллюстрации, анимации транзакций, микро-копирайтинг, аксессибилити (Dynamic Type, VoiceOver). |

## Краткий план внедрения

1. **Транспорт и протокол**: апгрейд до WalletConnect 2.0, мультичейн, миграция существующих хендлеров.
2. **Безопасность**: Secure Enclave/Keychain, биометрия, защита от фишинга (domain-binding), анти-фрод для подозрительных запросов.
3. **UX/UI**: SwiftUI-компоненты, темы, офлайн-режим, тултипы по разрешениям, экран диагностики.
4. **Продвинутая транзакционная модель**: трекинг статуса, ретраи, авто-газ, интеграция с ODIN staking/vesting/governance.
5. **Надёжность**: телеметрия, крэш-репорты, e2e тесты на реальные RPC, UI-тесты для онбординга и подтверждения транзакций.
